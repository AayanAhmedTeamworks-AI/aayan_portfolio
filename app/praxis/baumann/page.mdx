Foremen finish their shifts covered in mud, with a dying phone battery and no appetite for opening a form. They will, however, pick up a phone and talk. That observation ran through every decision on **Bautagesbericht Pro** — the construction daily-reporting PWA I led the front-end on during my internship at Teamworks AI, for Baumann GmbH.

In the German construction industry the *Bautagesbericht* is a legally significant document recording daily site activity, weather, personnel, materials, and incidents. Traditionally it is filled in by hand or in Excel at the end of a long shift — a workflow that is slow, error-prone, and impossible to query analytically. The brief was to replace that workflow with something a foreman could actually use in the cold, with muddy gloves, on a marginal LTE signal.

## Architecture

A React 18 / TypeScript 5.9 single-page app, bundled by Vite with the SWC plugin for sub-second rebuilds. State is split between TanStack Query for server cache and React Hook Form with Zod for validated form state. Persistence lives in Supabase — PostgreSQL with row-level-security policies per role, Supabase Storage for photographic evidence, and Deno-based Edge Functions for operations that cannot be trusted to the client.

## Offline-first, not offline-tolerant

Construction sites lose connectivity often enough that *graceful offline* is not a feature — it is the design centre. Every report is written first to IndexedDB via `idb`, queued through a custom sync-manager, and reconciled against Supabase when the network returns. A Workbox service worker handles asset caching and background sync. Each queued entry carries a client-generated UUID so the server can deduplicate retries safely.

A foreman can fill in a report, walk into a tunnel, have the OS kill the tab mid-save, reopen the app an hour later, and find the draft intact.

## The Fonio voice agent

The single most distinctive feature of the platform is a telephony-first reporting workflow, built on [fonio.ai](https://fonio.ai), a German conversational-AI telephony provider. A foreman either dials a dedicated project number or receives an outbound call from the Fonio agent at an agreed time. The agent conducts a structured German-language conversation covering site, weather, personnel, work performed, materials, incidents, and open to-dos.

At end-of-call, Fonio POSTs a webhook payload to a Supabase Edge Function, which identifies the caller by normalised E.164 phone number, passes the transcript to OpenAI with a strict JSON schema, and writes the extracted report to the database as a draft. The foreman reviews and approves on a phone or tablet the next morning — or the office does it for them.

## Roles, RLS, and translation

Three roles: **laborer** submits reports through a voice-first UI, **foreman** reviews and approves, **manager** handles analytics and administration. Role separation is enforced both on the client and authoritatively by Postgres row-level-security policies. A missing RLS policy on a protected column now fails a pre-commit lint pass; it is not a code-review concern any more.

Baumann's workforce speaks German as the default, with substantial numbers of workers speaking Arabic, Turkish, Polish, Romanian, and Croatian. The application is localised through `i18next` into seven languages, with right-to-left layout support for Arabic. A pre-commit script walks the source for every `t()` call, collects the keys, and fails the commit if any locale file is missing one. The class of *missing translation* bugs has effectively been extinguished.

## Auxiliary features

Beyond the core reporting flow I implemented an address autocomplete via a geocoding service, a barcode scanner for material tracking using the browser's native `BarcodeDetector` API with a WASM fallback, PDF export with localised templates, and a Juracheck dialog that routes ambiguous legal-compliance questions to an LLM for triage.

Each of these is a thin feature. The value is that the app is now the place where the foreman already is, so adding a fifteenth thing costs one morning instead of a project.
